# Security Model

## Trust Boundary

The browser is untrusted. Authentication, authorization, object ownership, storage access, download limits, and security-sensitive state changes are enforced on the server.

## Authorization

Roles are not sufficient on their own. Protected resources should also verify object ownership or the relationship between the authenticated user and the requested project, file, notification, or delivery.

## Files

Uploaded filenames are treated as data. Object keys are generated by the application rather than trusting user-provided paths. Private storage is accessed through authorized server operations and short-lived signed URLs.

## Public Deliveries

Share tokens are security credentials and must not be logged. Expiration, activation state, optional password protection, and download limits are evaluated server-side.

## User Content

Customer names, project names, filenames, notes, and notifications are untrusted strings. Render them as text rather than arbitrary HTML.

## Sessions and Cookies

Use HTTPS in production and keep authentication secrets outside source control. Account-state changes should invalidate access through the application's session-version mechanism.

## Security Review Checklist

- [ ] Authentication boundaries
- [ ] Object-level authorization / IDOR
- [ ] Upload path and filename handling
- [ ] MIME and size validation
- [ ] XSS-safe rendering
- [ ] Open redirect inputs
- [ ] CSRF and cookie settings
- [ ] Share-link token handling
- [ ] Signed URL lifetime
- [ ] Rate limits
- [ ] Logging redaction
- [ ] Dependency vulnerabilities
